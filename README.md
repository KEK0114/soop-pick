# 좋아요 순위

> **올리는 법은 맨 아래 [부록] 을 보세요.** GitHub 에 올리고 Vercel 에 연결하면
> 끝입니다. 그 뒤로는 `git push` 할 때마다 1분 안에 자동으로 갱신됩니다.

SOOP 방송국 게시글에 달린 **댓글을 좋아요 순으로** 줄 세우는 화면입니다.
스트리머가 컨텐츠 참가자를 뽑을 때 쓰라고 만들었습니다.

주소만 주면 누구나 봅니다. 로그인도 가입도 없습니다.

```
https://<사이트>/?post=https://www.sooplive.com/station/dalchesom/post/201070387&n=20
```

## 1. 문구나 색을 바꾸고 싶을 때 → `config.js`

`index.html` 은 열지 마세요. `config.js` 만 고치면 됩니다.

```js
window.PICK_CONFIG = {
  title: '좋아요 순위',              // 맨 위 제목
  subtitle: '...',                  // 그 아래 설명 (HTML 됩니다)
  defaultPickCount: 20,             // '뽑을 인원' 처음 값
  defaultPostUrl: '',               // 늘 같은 글만 본다면 여기에

  colors: { accent: '#4c8dff' },    // 바꾸고 싶은 것만

  show: {                           // 끄고 싶은 것을 false 로
    followers: true,                //   팔로워 수
    checked: true,                  //   '아직 확인 안 함' 표시
    photos: true,                   //   댓글에 붙은 이미지
    search: true,                   //   찾기 칸
  },

  footer: ['맨 아래 안내문', '줄마다 하나씩'],
};
```

고친 뒤:

```bash
git add . && git commit -m "문구 수정" && git push
```

Vercel 이 알아서 다시 올립니다 (보통 1분 안쪽).

## 2. 두 가지 보기

| 버튼 | 무엇 |
|---|---|
| **전체 종합표** | 순위를 한눈에 훑는 표. 기본값입니다 |
| **지원서 보기** | 지원서 전문이 카드로 죽 나오는 판 |

**지원서 보기**에서는 글이 **전부 펼쳐진 채로** 나옵니다. 훑는 것은 표가 하니
이 판은 읽는 데만 쓰라고 접지 않습니다.

표에서 **줄을 누르면 그 사람 지원서**가 뜹니다. 창 안에서 **← →** (또는 앞/뒤 버튼)로
다음 사람으로 넘어갈 수 있어 죽 훑기 좋습니다. **Esc** 나 바깥을 누르면 닫힙니다.

보기 방식도 주소에 담깁니다(`view=card`).

## 3. 스트리머 확인 표시

SOOP 게시글에서 글쓴이(스트리머)가 댓글에 누르는 **하트**는 "좋다" 가 아니라
**"이 지원서를 확인했다"** 는 뜻입니다. 그래서 이 화면은 확인한 쪽에 표를 달지
않습니다 — 마감된 글은 전원이 확인 상태라 똑같은 표가 수십 개 찍힐 뿐입니다.

**아직 안 본 쪽**에 답니다. 모집 중에 스트리머가 궁금한 건 그것이기 때문입니다.

- 목록 위에 `스트리머가 아직 안 본 것 N명` 이 나옵니다
- **[아직 확인 안 한 것만 (N명)]** 단추로 그것만 봅니다
- 전원 확인되면 `확인` 칸이 통째로 사라지고 `스트리머가 전부 확인함` 이라고만 뜹니다

## 4. 애청자 공개 게시판

게시판이 **애청자 공개**면 글 정보는 막힙니다(`403 · 이 게시판은 애청자
공개입니다`). 그런데 **댓글은 그대로 읽힙니다**(실측).

그래서 글을 못 읽어도 **순위는 그대로 나옵니다.** 제목과 본문 자리에만
왜 안 나오는지 적힙니다. 뽑는 데 필요한 것은 댓글이라 이걸로 충분합니다.

## 5. 관리자 모드 — 뽑을 때

주소 끝에 **`&admin=1`** 을 붙이면 각 줄에 버튼이 생깁니다.

| 버튼 | 하는 일 |
|---|---|
| **확정** | 그 사람을 맨 위로 올립니다. 좋아요와 상관없이 뽑을 사람 |
| **제외** | 목록에서 뺍니다. 중복 지원이나 조건 미달인 사람 |

고른 것은 **주소에 담깁니다** (`ex=...`, `fix=...`). 저장하는 곳이 없으니
서버도 계정도 필요 없고, 그 주소를 그대로 남에게 주면 같은 순위가 보입니다.

관리자 줄의 **[보는 사람용 주소 복사]** 를 누르면 `admin=1` 이 빠진 주소가
복사됩니다. 그걸 시청자에게 뿌리면 됩니다 — 버튼은 안 보이고 순위만 보입니다.

> 관리자 모드는 **암호가 아닙니다.** 주소를 아는 사람은 누구나 켤 수 있습니다.
> 다만 켜도 **자기 화면에서만** 바뀝니다 — 저장되는 곳이 없어서 남의 화면은
> 그대로입니다. 진짜로 막아야 하면 서버가 필요합니다.

## 6. 화면을 크게 고치고 싶을 때 → `index.html`

한 파일에 다 들어 있습니다. 위에서부터:

| 자리 | 무엇 |
|---|---|
| `<style>` | 색·모양. 색은 맨 위 `:root` 의 변수만 바꿔도 됩니다 |
| `API_POST` · `API_COMMENT` · `API_STATION` | SOOP 주소 세 개 |
| `parsePost()` | 붙여넣은 주소에서 아이디·글번호 뽑기 |
| `load()` | 글과 댓글 가져오기 (30개씩 나눠 오는 것을 끝까지) |
| `ranked()` | 최종 줄 세우기 (제외 빼고, 확정 올리고) |
| `paintList()` | 지원서 카드 그리기 |
| `paintTable()` | 전체 종합표 그리기 · 커트라인 · 동점 경고 |
| `openDetail()` | 줄을 눌렀을 때 뜨는 지원서 창 |
| `syncUrl()` | 지금 상태를 주소에 담기 |

고친 뒤에는 **실제로 눌러 보고** 올리세요:

```bash
cd soop-pick
python -m http.server 8777        # http://127.0.0.1:8777 에서 열립니다
```

## 7. 표시 두 가지 — 헷갈리기 쉬운 것

| 화면의 표시 | 어디서 오나 | 뜻 |
|---|---|---|
| **베스트 BJ** | 방송국의 `is_best_bj` | SOOP 이 준 그 사람 **등급** |
| ~~베스트~~ (없앰) | 댓글의 `isBestTop` | SOOP 이 좋아요 상위 **3개 댓글**을 위로 올린 것 |

`isBestTop` 은 스트리머 등급이 아니라 **댓글 순위**입니다. 확인해 보니 딱
1·2·3등에만 붙어 있었습니다 — 순위 칸에 이미 있는 정보라 없앴습니다.
'베스트' 라고만 적혀 있어 **베스트 스트리머로 오해**되기도 했습니다.

진짜 등급은 방송국에서 옵니다. 팔로워를 부르는 김에 같이 받으므로
부르는 횟수는 그대로입니다.

## 8. 글에서 읽어내는 것

모집 글에는 보통 마감·인원·프리패스가 적혀 있습니다. 붙여넣기만 하면
읽어서 알려 줍니다. **읽은 근거(원문 줄)를 같이 보여주므로** 틀렸는지
바로 알 수 있습니다.

| 읽는 것 | 예 |
|---|---|
| **신청 마감** | `신청 마감 : 8월 1일 23시 59분` → 지났으면 경고 |
| **선발 인원** | `선정 방식 : … 6~70명` → `[70명으로 맞추기]` (범위면 큰 쪽) |
| **프리패스** | `아래 인원은 프리패스 입니다!` 뒤의 명단 → 지원자 중에 있으면 표시 |

항목 이름과 값이 **다른 줄에 있어도** 잡습니다(실측: `선정 방식 :` 다음 줄에
`UP순 참고한 옾덜식 6~70명`).

### 엑셀로 내려받기

`[엑셀로 내려받기]` 를 누르면 지금 보이는 순위가 그대로 **엑셀 파일(.xlsx)** 로
떨어집니다. 머리글은 굵게, 첫 줄은 틀고정, 자동필터까지 걸어서 나옵니다.

칸: 순위 · 뽑힘 · 닉네임 · 아이디 · 좋아요 · (마감했으면) 지금 좋아요 ·
팔로워 · 스트리머 확인 · 등급 · 확정 · 댓글 시각 · **지원서 전문** ·
사진 주소 · 방송국 주소. 맨 아래에 언제 기준인지와 게시글 주소를 남깁니다.

- 화면의 찾기·`아직 확인 안 한 것만` 은 파일에 영향을 주지 않습니다. **전원**이
  들어갑니다. 대신 `뽑힘` 칸에 자동필터가 걸려 있으니 엑셀에서 걸러 보면 됩니다.
- `제외` 한 사람은 화면과 마찬가지로 빠집니다(몇 명 뺐는지는 맨 아래에 적힙니다).
- 끄려면 `config.js` 의 `show.excel` 을 `false` 로.

**바깥 라이브러리를 안 씁니다.** xlsx 는 XML 몇 장을 zip 으로 묶은 것이라,
필요한 만큼만 `index.html` 안에서 만듭니다(zip 은 압축 없이 '저장' 방식).
CDN 이 죽어도 이 버튼은 그대로 됩니다.

### 짧은 주소 — Vercel Blob 붙이기

`config.js` 의 `shortLinks` 가 켜져 있고 Blob 저장소가 붙어 있으면 완전 고정
주소가 `.../p/a1b2c3d4` 로 나옵니다. 저장소가 없으면 결과를 통째로 담은 긴
주소가 나옵니다.

붙이는 순서:

1. Vercel 대시보드 → 이 프로젝트 → 왼쪽 사이드바의 **Storage**
2. **Create Database** → **Blob** → 이름 아무거나 → 접근은 **Private**
3. 이 프로젝트에 **Connect**. 그러면 필요한 환경변수가 저절로 붙습니다.

붙여넣을 주소도, 복사할 키도 없습니다. 3번까지 하면 끝입니다.

**왜 Private 인가.** 여기 담기는 것은 남의 **지원서 전문**입니다. 공개 저장소로
두면 그 파일이 인터넷에 그대로 노출된 주소를 갖게 되고 검색엔진에도 잡힐 수
있습니다. Private 이면 반드시 `api/pin.js` 를 거쳐야 읽힙니다.

동작:

- `[완전 고정 주소 복사]` → 결과가 저장되고 `/p/a1b2c3d4` 가 복사됩니다.
- `[보는 사람용 주소 복사]` → 설정만 저장되고 `/v/a1b2c3d4` 가 복사됩니다.
  이쪽에는 사람 목록이 안 들어갑니다. 글 주소·뽑을 인원·마감 시점·확정/제외뿐이라
  아주 작습니다. 순위는 보는 사람 브라우저가 SOOP 에서 그때그때 받아 옵니다.
- **저장이 안 되면 긴 주소로 그냥 떨어집니다.** 링크를 못 만드는 일은 없습니다.
- 이름은 **내용으로 짓습니다**(내용의 해시 앞 10자). 같은 결과를 두 번 저장해도
  주소가 하나입니다. 실수로 두 번 눌렀다고 링크가 갈리지 않습니다.
- 한 번 만들어진 결과는 안 바뀌므로 브라우저에 1년 캐시로 내려보냅니다.
- `api/save.js` 는 우리 화면이 만든 모양인지 확인하고 400KB 를 넘으면 거절합니다.
  남의 파일 보관함으로 쓰이지 않게 하는 최소한의 장치입니다.

**한도** (Hobby, 2026-09 기준): 저장 5GB · 쓰기 1만 회/월 · 함수 호출 100만 회/월.
결과 하나가 3~25KB 이니 월 1만 건을 공개해도 한도 안입니다. Hobby 는 **한도를
넘어도 요금이 청구되지 않습니다** — 30일간 그 기능이 멈출 뿐입니다. 다만 Hobby 는
**비상업·개인 용도**로 제한됩니다.

**주의**: 저장소를 지우거나 프로젝트를 없애면 그동안 뿌린 짧은 주소가 전부
죽습니다. 오래 남겨야 하는 결과는 긴 주소(`#pin=`)로도 하나 받아 두세요. 그건
사이트만 살아 있으면 열립니다.

### 완전 고정 주소 — 아무도 못 바꾸는 결과

표 바로 위 **남에게 주기** 칸의 `[완전 고정 주소 복사]` 는 **결과를 주소 안에 통째로**
담습니다. 순위·닉네임·아이디·좋아요·팔로워·등급·확인 여부·지원서 전문·사진까지.

그 주소로 들어온 사람 화면은 **SOOP 를 한 번도 부르지 않습니다.**

- 게시글이 지워져도, SOOP 가 API 를 바꿔도 그 화면은 그대로입니다.
- 새로고침도 마감도 없습니다. 바뀔 수가 없습니다. 남는 건 보기와 엑셀뿐입니다.
- 서버가 필요 없습니다. 저장하는 곳이 없으니 지워질 것도 없습니다.

대신 **주소가 깁니다.** 길이의 거의 전부가 **지원서 내용**입니다.

| 6명짜리 글 실측 | 주소 길이 |
|---|---|
| 지원서까지 전부 | 약 1,900자 |
| **`지원서 내용도 담기` 를 끄면** | **약 340자** |

그래서 버튼 옆에 그 체크칸을 뒀습니다. 순위만 보여 줄 거면 끄세요 — 받는 사람
화면에서 지원서 칸이 통째로 사라지고 주소가 5분의 1로 줄어듭니다. 켠 채로 두면
지원서 전문까지 그대로 남습니다. 어느 쪽이든 길이를 미리 적어 둡니다.

브라우저는 긴 주소를 문제없이 다루지만, 메신저에 따라 잘라 버릴 수 있습니다 —
링크가 안 열린다는 말을 들으면 주소가 잘린 것입니다. 그럴 땐 지원서를 빼세요.

주소를 더 줄이려면 결과를 어딘가에 **저장**하고 짧은 주소를 발급하는 수밖에
없는데, 그건 서버가 필요합니다. 이 도구는 서버 없이 도는 쪽을 골랐습니다.

주소는 `#pin=...` 모양으로 **`#` 뒤**에 담깁니다. `#` 뒤는 서버로 전송되지
않으므로, 지원서 내용이 남의 서버 기록에 남지 않고 주소가 길다고 거부당하지도
않습니다.

세 가지 주소를 구별하세요.

| 주소 | 받은 사람이 보는 것 | SOOP 를 부르나 |
|---|---|---|
| 그냥 주소 | 지금 순위. 모든 버튼 | 부름 |
| `[보는 사람용 주소]` (`ro=1`) | 지금 순위. 보기 전용 | 부름 |
| `[완전 고정 주소]` (`#pin=`) | **고정된 순위. 안 바뀜** | **안 부름** |

### 남에게 줄 때 — 보기 전용

표 바로 위 **남에게 주기** 칸의 `[보는 사람용 주소 복사]` 로 나오는 주소에는
`ro=1` 이 붙습니다. 그 주소로 들어온 사람에게는

- 게시글 주소 붙여넣는 칸 · 뽑을 인원 · `[불러오기]` — **안 보입니다**
- `[지금으로 마감]` · `[마감 풀기]` — **안 보입니다**
- 관리자 버튼 — 안 보입니다

`[새로고침]` · `[엑셀로 내려받기]` · 표/지원서 보기 전환 · 찾기 ·
`[뽑힌 사람 복사]` 는 그대로 됩니다.

> **자물쇠가 아닙니다.** 주소에서 `ro=1` 을 지우거나 사이트를 그냥 새로 열면
> 입력칸이 다시 나옵니다. 남의 순위를 망칠 수는 없고(마감 결과는 그 사람이
> 받은 주소 안에 들어 있습니다), 헷갈려서 잘못 누르는 것을 막는 용도입니다.
> 정말 못 보게 해야 하는 내용이라면 이 주소를 주지 마세요.

### 마감 시점 고정 — [지금으로 마감]

**SOOP 은 "지금 좋아요"만 줍니다.** 8월 1일에 몇 개였는지는 안 알려줍니다.
그래서 마감이 지난 글을 나중에 열면 그 뒤로 쌓인 좋아요까지 섞입니다.

**마감 즈음에 [지금으로 마감]을 한 번 누르면** 그때 순위가 그대로 얼어붙습니다.

- 얼리는 것은 **아이디와 그때의 좋아요 수**뿐입니다. 글·사진·프로필은 안 변하니
  볼 때마다 새로 받습니다. 그래서 담을 것이 작아 **주소 하나에 다 들어갑니다**
  (82명 = 1.4KB). 파일도 서버도 필요 없고, 그 주소를 주면 남도 같은 순위를 봅니다.
- 마감 뒤에 달린 댓글은 **뺍니다**(마감 뒤 지원은 지원이 아니므로).
- 마감 뒤에 좋아요가 바뀐 사람은 `723 (지금 731)` 처럼 **둘 다** 보여줍니다.
- **[마감 풀기]** 로 언제든 지금 값으로 되돌립니다.
- 마감 결과는 **주소 안에** 들어갑니다. 서버에도 그 PC에도 저장되지 않으니,
  주소를 복사해 두지 않고 창을 닫으면 사라집니다. 그 주소를 남에게 주면
  그 사람에게도 **똑같이 마감된 순위**가 보입니다.

지원자가 아주 많으면(수백 명) 주소가 길어집니다. 대략 **100명에 1.7KB** 이니
500명이면 8KB 쯤 되는데, 메신저에 따라 잘릴 수 있습니다.

### 지난 마감은 되돌릴 수 없습니다

**SOOP 은 "지금 좋아요"만 줍니다.** 8월 1일에 몇 개였는지는 안 알려줍니다.
그래서 마감이 지난 글을 지금 열면 그 뒤로 쌓인 좋아요까지 섞여 있습니다.
읽어낸 마감으로 **며칠이 지났는지 경고**는 하지만, **이미 지난 마감은 되돌릴 수
없습니다.** 마감은 누르는 그 순간을 찍는 것이라, 마감 전에 한 번은 눌러 두어야
합니다.

프리패스는 **`프리패스?`** 처럼 물음표를 붙입니다 — 글의 명단에 그 닉네임이
있다는 것뿐이라 동명이인일 수 있어서, 사람이 확인하라는 뜻입니다.

## 9. 규칙 (일부러 이렇게 한 것)

- **순위는 좋아요 하나로만** 매깁니다. 팔로워는 보여 주기만 하고 순위에 안 넣습니다.
- 한 사람이 댓글을 여러 개 달았으면 **좋아요가 가장 많은 것** 하나만 셉니다.
  (지원 글을 고쳐 쓰느라 두 번 다는 일이 흔합니다)
- 답글(대댓글)은 지원으로 세지 않습니다.
- 좋아요가 같으면 **먼저 쓴 사람**이 위로 갑니다.
- 커트라인 바로 위아래가 **동점이면 경고**를 냅니다. 선만 긋고 넘어가면
  사람이 정해야 할 자리를 놓치기 때문입니다.

## 10. SOOP 가 막으면

지금은 SOOP API 가 CORS 를 열어 두고 있어서 브라우저가 직접 부릅니다.
나중에 막히면 중계 서버가 하나 필요합니다. `config.js` 의

```js
apiBase: 'https://soopchat.duckdns.org/pick-proxy'
```

를 채우고, `index.html` 위쪽의 `API_*` 세 줄이 그걸 쓰게 하면 됩니다.
그 외에는 고칠 것이 없습니다.

## 11. 쓰는 API

| 무엇 | 주소 |
|---|---|
| 글 | `api-channel.sooplive.com/v1.1/channel/{아이디}/post/{글번호}` |
| 댓글 | 위 주소 + `/comment?page=N&perPage=30` |
| 팔로워 | `chapi.sooplive.co.kr/api/{아이디}/station` → `station.upd.fan_cnt` |

댓글 하나에 들어 있는 것: `userId`, `userNick`, `profileImage`, `comment`(글 전문),
`likeCnt`(좋아요), `bjlike`(스트리머가 확인했나), `photo`, `regDate`.
방송국(`station`)에서는 `upd.fan_cnt`(팔로워) · `is_best_bj` · `is_partner_bj` 를 씁니다.

# [부록] 올리는 법

## 처음 한 번 — GitHub 에 올리고 Vercel 에 연결

**1. GitHub 에서 빈 저장소를 만듭니다.**
이름은 아무거나 (예: `soop-pick`). README·.gitignore 는 **체크하지 마세요**
(여기 이미 있습니다).

**2. 이 폴더를 그 저장소로 올립니다.** 이 폴더에서:

```bash
git remote add origin https://github.com/<내아이디>/soop-pick.git
git branch -M main
git push -u origin main
```

**3. Vercel 에 연결합니다.**
[vercel.com](https://vercel.com) → **Add New… → Project** → 그 저장소를 **Import**.
설정은 **아무것도 건드릴 필요 없습니다** — 정적 파일이라 Vercel 이 알아서 잡습니다.
(Framework Preset 이 `Other` 로 잡히면 그대로 두면 됩니다)

**Deploy** 를 누르면 `<이름>.vercel.app` 주소가 나옵니다. 그게 끝입니다.

## 그다음부터 — 고치고 올리기

```bash
# 고친 뒤
git add .
git commit -m "무엇을 고쳤는지"
git push
```

Vercel 이 알아서 다시 올립니다. 보통 **1분 안쪽**입니다.
